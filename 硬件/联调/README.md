## 第一阶段：OLED + Wi-Fi + 读取计划

打开 [BoxOLEDClient/BoxOLEDClient.ino](BoxOLEDClient/BoxOLEDClient.ino)。只使用原先 OLED 接线：VCC→3V3、GND→GND、SDA→D21、SCL→D22，地址 0x3C，128×64。修改接线前先拔 USB。不操作 D25/D33，不响铃、不检测门磁，也不上传或模拟开盒。

- 本机 `BoxOLEDClient/secrets.h` 保存原来热点配置，由旧 `测试/WiFiOLED/secrets.h` 复用；该私有文件被 Git 忽略。换热点时在本机修改，不把真实密码发到聊天或提交仓库。公开模板为 `wifi.example.h`。
- `config.h` 的默认后端为当日电脑 WLAN 地址；换网络可从串口发送 `server http://新的电脑IP:8766`。不能用 127.0.0.1 或 ESP32 自身 IP。
- Arduino 选 ESP32 Dev Module，选择实际 COM7，上传后串口监视器设为 115200，并选择发送新行。屏幕应显示 `Box stage1: READ ONLY`，联网后显示 ESP32 IP。
- 未绑定设备时显示 `Need binding`；这表示 OLED/联网阶段可以继续检查，并不是上传失败。

## 绑定原型测试家庭

1. 用独立测试家庭或公共演示家庭操作，不能把原型记录混入真实日常用药。后端需通过“启动局域网联调”监听电脑局域网；电脑和 ESP32 连接同一热点。
2. 小程序“我的 → 硬件接入与设备设置”查看设备编号并生成设备密钥。换密钥会让旧密钥失效；不要在其他家庭或已有设备上随意重置。
3. 在串口输入一行 `bind 设备编号 设备密钥`，发送。程序只提示保存结果，不回显密钥；绑定保存在开发板本地 NVS，断电后保留，不是加密保险箱。
4. 成功时显示 `Schedule OK`，AM/NO/PM 分别显示三时段和计划项数，无计划显示 `no plan`；串口显示 `GET /api/device/schedule -> 200`。不会显示假装完成的开盒事件。
5. 发送 `r` 可立即重读计划；正常情况下每 60 秒更新计划，失败后每 15 秒重试。此为业务计划读取，不新增心跳或在线判定。

串口 `?` 查看当前状态和帮助。`unbind` 只清除开发板本地绑定，不撤销服务端密钥。程序不打印 Wi-Fi 密码、设备令牌或完整家庭药单。

## 排错与下一步

| 屏幕/串口 | 先检查 |
| --- | --- |
| 屏幕不亮、串口 OLED not detected | 断电后核对 OLED 的 3V3/GND/D21/D22；保留原有屏幕测试例程排查 |
| WiFi connecting | 当前热点是否开启、是否是原来配置；先用串口 `?` 看状态 |
| Need binding | 还没写入设备编号与密钥，需要完成绑定 |
| PC unreachable | 电脑和开发板是否同网、后端是否监听局域网、IP 与端口是否正确 |
| Key invalid / HTTP 401 | 密钥是否来自当前家庭设备设置、是否已被更换；重新绑定当前有效密钥 |
| Schedule OK + no plan | 连接已成功，但该家庭当天该时段没有启用计划，不是传感器故障 |

本阶段通过后，先断电接好门磁，使用旧 `ReedOLED` 或 `ReedBuzzerTest` 检查稳定的 0/1 和关盖极性；再接蜂鸣器做独立驱动检查。取得实物结果后再加入按计划提醒和真实开盒上传，不能用当前只接 OLED 的状态宣称完整药盒功能已经完成。

官方 API 依据：[Wi-Fi](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/wifi.html)、[Preferences](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/preferences.html)。
