# 联网药盒固件

正式联动程序位于 [`MedicineBox/MedicineBox.ino`](MedicineBox/MedicineBox.ino)。它把已验证的 OLED、门磁、蜂鸣器接线与现有后端 `GET /api/device/schedule`、`POST /api/device/events` 接起来，不发送心跳。旧的 `BoxOLEDClient` 和独立 `DailyReminderTest` 仍保留作分阶段诊断。编译和烧录不能代替账号绑定、计划下发与实物响铃验收。

## 使用前

1. 接线：OLED SDA=GPIO21、SCL=GPIO22，低电平蜂鸣器 I/O=GPIO25，门磁=GPIO33 与 GND；门磁默认贴磁铁关盖电平为 0。电源分线与电气规格仍按[全部硬件接线表](../../../项目文档/全部硬件接线表.md)检查。
2. `MedicineBox/wifi.example.h` 复制为同目录 `secrets.h`，填写连接后端电脑所在局域网的 2.4GHz Wi-Fi。`secrets.h` 已被 Git 忽略；本机若已有阶段一私有配置，可直接复用。
3. 当前实物只有一个门磁，用户确认装在**早药格**，故固件 `MedicineBox/config.h` 的 `SENSOR_SLOT_KEY` 为 `morning`；真实家庭的自动“未开盒”通知也只针对早药格。中、晚药格仍可保存计划和显示逾期，但因没有门磁，不发送设备未开盒通知。日后改装时，固件映射和后端 `monitoredSlots` 必须一起调整。
4. 电脑运行根目录 `启动局域网联调.bat`；小程序登录页的连接设置填写电脑局域网地址。ESP32 固件也须使用同一电脑局域网地址，不能填 `127.0.0.1`。

## 首次绑定

小程序“我的 → 硬件接入与设备设置”显示本家庭 `MG-...` 设备编号，并可生成专用接入密钥。**如果已有有效密钥并已在设备中使用，不要重复生成；新密钥会立即废止旧密钥。**

将固件编译上传后，电脑用 115200 波特率打开 ESP32 串口，发送以下命令（每行以换行结束；替换占位内容）：

```text
server http://电脑局域网IP:8766
bind MG-你的设备编号 仅显示一次的设备密钥
?
```

看到 `Schedule OK` 表示密钥和服务端计划读取成功。串口 `?` 查看状态、事件队列与门磁电平；`r` 立即重拉计划；`c` 在**确认盒盖已关好**时保存关盖电平；`s` 停止当前响铃；`unbind` 仅清除设备本地绑定，不撤销服务器密钥。固件不会回显密钥。此前阶段一固件使用的绑定存在同一个 NVS 命名空间，若已绑定可直接读取。

## 时间与开盒规则

- HTML 预览页或小程序“计划”中新增、修改早药格提醒时间，设备每 10 秒重新拉取当日计划并用 `serverTime` 校时。提醒窗口为 30 分钟，另有 15 分钟宽限；未开盒且家属未确认时，**到点响三声**，此后每 10 分钟**连续响 5 秒**，最多 4 次。以 08:00 为例：08:00 三声，08:10、08:20、08:30、08:40 各响 5 秒；到 08:45 仍未处理则**连续响 15 秒**，后端进入家属通知流程。时间由账号里的计划决定，不固定为 08:00。
- 在截止前真实开盒，门磁去抖后发出**两声短确认音**（每声约 0.2 秒），停止本次后续提醒并上传开盒事件。家属也可在小程序“药盒”或“提醒”页确认本次情况；固件联网取得 `CONFIRMED` 状态后停止响铃，后端取消尚未发出的本次超时通知。家属确认与真实开盒分开记录，不代表已服药；已发出的通知无法撤回。串口发送 `t` 可只测试两声，不生成开盒事件。
- 只在门磁去抖后的真实**关→开**边沿记录事件；上电时已经开着，不算一次开盒。只有当天该药格存在计划、设备时钟已校准、开盒时间不早于计划开始时才上传。同一个计划开始时间只记一次；同日删除旧计划并设置新的未来时间，可重新演示。尚未上传的同日开盒事件会暂时阻止重复记录，直到上传成功或用户明确执行“重置今天的演示记录”。时间带 `+08:00`。后端的“已开盒”只表示实际发生开盒，不能证明吞服。
- HTML/小程序“我的 → 重置今天的演示记录”只清除当天提醒和开盒测试记录，保留账号、计划与设备绑定。药盒下次拉计划时自动清除当天本地测试状态；旧计划时间若已过去会保持静音，须改设未来时间再演示。已发出的微信消息无法撤回。
- 事件先写入 ESP32 NVS 队列，网络恢复后以同一个 `eventId` 与正文重试；后端重复事件不会重复计入。队列最多 8 条，满时串口和屏幕提示，不能默默当作上传成功。401/403 时核对绑定；409/422 时保留待人工检查。时间、计划未成功读取或本地存储不可用时，不生成事件。
- 断网后，当日已获取的计划及 ESP32 时钟仍可继续工作；重启后必须重新连到后端获取时间与当天计划。跨天断网不能凭旧计划提醒。固件不推断在线/离线，也不发送心跳。

## 建议验收顺序

1. 串口确认 `WiFi connected`、`Schedule OK`，OLED 显示当前计划；在小程序修改计划时间后约 10 秒内核对屏幕更新。
2. 仅用测试家庭和模拟物，关闭盒盖后打开一次；查看串口 `POST event -> 200`，小程序“历史”显示“真实设备”，设备页显示“曾接入硬件”。重复断网重试不应新增第二条历史。
3. 用可等待的测试计划验证到点三声、此后每 10 分钟连续 5 秒、窗口内开盒两声、截止时连续 15 秒；开盒或家属手机确认应停止后续铃与尚未发出的超时通知。
4. 家属在小程序“提醒”页主动授权，后端配置真实微信模板后，关闭小程序验证手机收到通知。代码检查、API 受理与页面状态都不能替代此实测。

本固件使用局域网 HTTP 供联调。对外正式发布需 HTTPS 后端、微信合法域名和安全的设备配网/密钥交付；不要把 Wi-Fi 密码、设备密钥或微信 AppSecret 放入仓库。
