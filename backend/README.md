# 安心药伴后端与演示

## 本地启动

在项目根目录双击 `启动演示.bat`，保持服务窗口打开。浏览器打开 `http://127.0.0.1:8766/preview`。

- “先体验演示家庭”可直接进入，不需要硬件。
- 演示账号：`13800000000`，密码：`Demo12345`。这是公开示例账号，请勿保存真实隐私。
- 注册的账号有独立家庭资料，初始没有用药计划。可以自行新增计划。
- 登录失败 3 次锁定 60 秒，次数保存在数据库中。密码使用带盐 PBKDF2 哈希；会话有效期 24 小时。
- 点击顶部“编辑”维护家庭档案；手机中的“我的”也提供档案编辑。

本版使用 SQLite，首次运行创建 `backend/data/medguard.sqlite3`，无需先配置 MySQL。数据库被 Git 忽略。关闭服务后数据保留；请勿把真实数据提交仓库。表结构由 `backend/main.py` 初始化，根目录的 `数据库` 文件夹预留后续设计与 SQL 脚本，目前只有占位文件。

启动脚本优先复用 `backend/.venv`，也能处理搬迁导致的旧 venv 启动器路径失效。若本机没有依赖环境，可在项目根目录用已安装的 Python 3.12+ 运行：

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
```

也可以手动启动：`python -m uvicorn backend.main:app --host 127.0.0.1 --port 8766`。可用 `MEDGUARD_DB` 环境变量更换数据库文件。

## 小程序与局域网

微信开发者工具导入 `微信小程序` 文件夹。开发者工具默认地址为 `http://127.0.0.1:8766`，与浏览器使用同一个后端。登录页“连接设置”可更换地址。开发阶段项目配置已关闭合法域名校验；如果工具仍拦截本地请求，请在工具的本地设置确认该选项。

手机真机/ESP32 联调：运行 `启动局域网联调.bat`，使服务监听 `0.0.0.0:8766`；手机、电脑和硬件连接同一局域网，连接地址填写电脑的局域网 IP，例如 `http://192.168.1.20:8766`。Windows 防火墙如有提示，仅允许所需的专用网络。正式发布还需部署 HTTPS 服务、配置微信合法域名及正式身份认证。

## 业务边界

- 首页只有问候、家庭场景、档案摘要与药盒入口；用药操作放在独立页。
- 本周为周一到周日，共 21 格。没有启用计划的药格不会记录为完成。
- 同一药格中的多项计划需要相同提醒时间，时间不一致时后端明确拒绝保存。
- 默认提醒窗口 30 分钟，随后宽限 15 分钟；未开盒且家属未确认时，从开始起每 10 分钟提醒一次，最多 5 次。到截止仍未处理则生成应用内家属提醒。家属可在小程序确认本次情况，使药盒停止后续响铃并取消尚未发出的超时通知；确认不等于已开盒或已服药。微信订阅通知需实际模板、服务端密钥和家属主动授权，尚未完成真机通知验证；短信和外呼未接入。
- 当前真实家庭只有早药格装有门磁，自动“设备未开盒”提醒仅针对早药格；中、晚计划仍可显示逾期，但不会因没有传感器而推送设备超时通知。演示家庭保留三时段演示提醒。
- 联网药盒固件已写入 `硬件/联调/联网药盒`，可读取服务端计划并驱动蜂鸣器、门磁和开盒上传；2026-11-11 已烧录到 COM7，账号绑定、同日重新设计划的到点三声、开盖两声和真实开盒上传已通过。后续 5 秒/15 秒铃和微信通知送达仍待实机验收。语音提醒未接入。
- 家属可在小程序“计划”页面修改或删除已有计划，设备正常联网后约每 10 秒获取新计划。`PUT /api/plans/{plan_id}` 更新详情，`DELETE /api/plans/{plan_id}` 删除计划；`PATCH` 用于启停。删除后保留已发生的开盒与提醒历史。
- 所有模拟开盒和逾期标记为“软件模拟”，不会产生真实硬件接入记录。真实设备需独立密钥认证。
- 开盒记录不等于已服药，不能作为医疗确认或紧急救援保障。

接口详见 `项目文档/硬件接入说明.md`。API 文档可在运行后访问 `/docs`。

## 关闭小程序后的家属通知

核心目标为“规定时间内未收到开盒记录 → 家属收到微信提醒”，不是开盖时响铃。后台每 5 秒独立推进时间规则，微信派发任务独立执行；不依赖家属打开页面。

将本目录 `.env.example` 复制为 `.env` 并在本机填写 AppID、AppSecret、实际订阅模板和字段映射，重启后端后，家属在小程序“提醒”页主动开启微信提醒。没有配置时不会向微信发送请求，原应用内提醒照常。完整说明见 [微信家属通知接入](../项目文档/微信家属通知接入.md)。

本机 SQLite 保存接收者绑定、估计授权次数和去重发件箱。演示家庭和模拟提醒不发真实微信消息；发送状态 `sent` 仅表示微信受理，不表示送达或已读。真实开盒上传已进行实物验收；微信接收的端到端实测尚未完成。

## 药品资料与自愿药友（2026-11-06）

新增实现位于 `backend/medicine_support.py`，沿用现有家庭 Bearer 会话与 SQLite 事务。启动时增量创建 `medicine_notes`、`companion_profiles`、`companion_requests`、`companion_messages`，无需手动迁移，不覆盖原记录。公网演示快照不随本次本地开发更新。

| 接口 | 用途 |
| --- | --- |
| `GET /api/medicines` | 当前家庭药品资料、一般储存提示、结构设计提示与来源 |
| `PATCH /api/medicines/{plan_id}` | 保存说明书资料；资料非空时 `source` 必填 |
| `GET /api/companions` | 自己的设置、可选计划、相同药名且已同意交流的人、邀请与药友 |
| `PATCH /api/companions/profile` | `enabled/alias/about/planId/participantConsent`；开启需本人同意 |
| `POST /api/companions/requests` | `targetId`，发出邀请 |
| `PATCH /api/companions/requests/{id}` | `action=accept/decline/cancel/disconnect`，按双方角色限制 |
| `GET/POST /api/companions/connections/{id}/messages` | 接受后双方访问最近 100 条消息；POST 为 `content`，1–500 字 |

药品资料只按当前家庭的计划读取/编辑；同药名共用资料，不推断适应症和剂量。药友以单项已启用计划的药名文字归一匹配，不合并别名或成分，不代表同病同药已被核验。推荐不带电话、住址、病历、完整药单；昵称和介绍是自愿填写。演示与独立家庭不互荐。

默认关闭，双方接受前不能聊天；仅当双方继续自愿开启、所选计划启用且话题一致时可访问。关闭、换药名、暂停所选计划和重置资料会结束关系，旧会话不再可读取/发送，重新开启不恢复旧关系。关闭不物理删除已存邀请/消息；真实开放前需完善留存和清除政策。邀请每天最多 20 次，消息每小时最多 60 条/账号。聊天不接微信推送，界面每 8 秒刷新，浏览器编辑时暂停刷新。

复现：注册两个测试家庭 → 各添加同名测试计划 → 分别从“我的”开启药友并确认同意 → 一方邀请 → 另一方接受 → 站内交流 → 任一方关闭或暂停所选计划，验证双方旧会话不可再访问。公共演示账号不会展示独立家庭。

## 验证

项目根目录运行：`python -m unittest discover -s 测试代码 -p 'test_*.py' -v`。
测试使用临时数据库，不污染演示数据。覆盖账号隔离、锁定持久化、计划、档案、模拟记录、设备认证、事件去重、无心跳接入、提醒时间规则，以及新增资料来源验证、药友同意/角色权限、撤回和退出、暂停计划、重置、消息及邀请限额。

新增原生页面行为检查：`node 测试代码/test_medicine_support.cjs`。浏览器双账号端到端检查：`node 测试代码/test_support_preview.cjs`，测试环境需可解析 `playwright` 并安装 Edge；可用 `MEDGUARD_TEST_PYTHON` 和 `MEDGUARD_TEST_BROWSER` 指定解释器与浏览器。浏览器测试自动创建临时数据库和端口，完成后关闭测试进程，不修改已有家庭数据。原生页面脚本与模板检查不能替代微信开发者工具编译和真机联调。
