## 核心闭环（2026-11-05 对齐）

核心功能是规定时间内未收到药盒开盒记录时通知家属，且家属关闭小程序也希望收到微信通知。正式蜂鸣器应按计划提醒老人；开盖短响只是独立检测测试，不作为正式提醒策略。后端负责超时判定和微信订阅通知，磁簧开关负责提供真实开盒事件，不新增心跳。

已新增微信授权入口与后端订阅发送代码，仍需实际模板、服务端配置、家属授权及真机接收验证；真实设备开盒上传尚待实现。完整进度与设置见 [微信家属通知接入](微信家属通知接入.md)。

## 原型与硬件路线

当前药盒原型不能真正存药，应在独立演示家庭内使用模拟计划和模拟物品。当前接口仍会把开盒关联为任务完成；原型体验与日常用药反馈的业务隔离尚待实现，不能把原型开盒作为真实用药结果。

硬件路线为 ESP32 + Arduino C/C++，通过 Wi-Fi/HTTP 接入。首版实现一个检测单元；2026-11-08 已取得该单元门磁、蜂鸣器及 OLED 本地功能测试的实物反馈，语音提醒后续考虑。已有基础练习源码保存在 `硬件/测试`，完整开盒上传固件尚未实现，21 个逻辑药格不代表完成了 21 格硬件。

## 简化接入方式

不需要心跳接口或定时保活，也不根据通信间隔判断在线/离线。固件只需拉取计划和上传真实开盒事件。首次有效开盒上传后，页面显示“曾接入硬件”；最后通信时间仅供查看历史，不代表实时在线。

开盒事件的 `battery` 可省略，范围 0–100；未上报时显示“待上报”。USB 供电阶段可不实现电量采集。

## 拉取计划 GET /api/device/schedule

响应包含 `deviceCode`、带 `+08:00` 的 `serverTime`、当天三个 `tasks` 及 `reminderPolicy`。每个任务具有 `id`、`date`、`slotKey`、`startAt`、`endAt`、`medicines`、`status`、`reminderCount`。`NO_MEDICATION` 的药格不需提醒。

`reminderPolicy`：`intervalSeconds=600`，`maxCount=5`，`graceSeconds=900`。当前联网固件在计划开始时响三声，10、20、30、40 分钟各连续响 5 秒；截止（开始后 45 分钟）未处理则连续响 15 秒。截止前真实开盒响两声短确认音，每声约 0.2 秒。家属通过 `POST /api/tasks/{task_id}/confirm` 可确认本次情况，任务状态变为 `CONFIRMED`，固件下次拉取后停止本次响铃；它不是开盒或已服药记录。后端仍保持 30 分钟提醒窗口与 15 分钟宽限；当前仅早药格有真实门磁。开机与运行期间拉取计划以校时，不使用心跳判断在线。

## 开盒事件 POST /api/device/events

```json
{
  "deviceCode":"从设置页获取",
  "eventId":"设备编号-20261015-080031-0001",
  "slotKey":"morning",
  "occurredAt":"2026-10-15T08:00:31+08:00",
  "battery":84
}
```

- `slotKey` 为 `morning` / `noon` / `evening`；第一版单格传感器可配置为其中一个时段，后续三格分别映射。
- 示例时间仅用于说明格式，实际上传必须为当前真实事件时间，带时区。
- 设备负责为每次开盒生成唯一 `eventId`。网络重试使用完全相同的正文和编号；服务端返回 `duplicate:true`，不重复记历史。同一编号不同正文返回 409。
- 服务端按事件日期与时段匹配当前展示周任务，拒绝无计划药格、未来超过 2 分钟、早于 7 天以及当前周之外的事件。断网缓存跨周补传需后续扩展历史任务接口，当前不可假装补传成功。
- 计划开始前的开盒不计入该次用药任务；联网固件同样只在计划开始后生成事件。开盒晚于通知截止仍可留下真实记录，但不回溯撤销已经送达的微信消息。
- 事件记录来源为 `hardware`；软件模拟来源为 `demo`；时间规则产生的逾期来源为 `rule`。
- 若先前进行过模拟开盒，后来的真实开盒仍会独立保存真实来源，不能被演示记录吞掉。
- 成功开盒事件保存最近通信时间，但不进行在线或离线判定；设备编号与密钥不匹配返回 403。

常见错误：401 密钥无效或缺失；403 编号不匹配；409 无计划/事件冲突；422 参数或设备时间不正确。

## 数据保护与范围

已有真实设备事件的家庭禁止演示重置。仅用于软件演示的家庭可通过确认对话框恢复初始状态。数据持久化在本机 SQLite，不会自动上传云端。后续正式部署应配置 TLS、设备安全存储、账号恢复和通知服务。

开盒不等于已服药。本项目辅助家属关注日常情况，无法核实吞服，也不替代医疗判断。

### 今天遇到的问题及解决方法

- CP2102 最初错误码为 28，缺少驱动；安装 CP210x 后解决。
- ESP32 支持包从 GitHub 下载超时，切换官方中国镜像 `https://espressif.github.io/arduino-esp32/package_esp32_index_cn.json`，选择 3.3.12-cn 后安装成功。期间镜像也曾超时，重试后成功。
- 编译报错 `exec: "cmd": executable file not found in %PATH%`；确认 cmd.exe 存在，仅在当前用户 Path 补充 `C:\Windows\System32`，保留原有条目，重新打开 IDE 后继续；程序编译通过。
- 串口乱码通过将监视器波特率与 `Serial.begin(115200)` 一致解决。
- SerialHello 只发文字给电脑；I2CScanner 只扫描地址。上传 OLEDHello 后才会向小屏幕发送显示内容。

- 随后用户明确确认磁铁贴近并保持，通过 COM7 发送 `c` 收到“已把当前状态记为关盖，电平 = 0”，随后 `GPIO33=0 | 关盖 | 蜂鸣器输出=HIGH(关闭)`；本次 RAM 关盖校准成功（本次磁铁贴近 = 0），重启须重新 `c`。
- 用户进一步确认移开磁铁并保持约 5 秒时自动响三声后停止，观察期间保持打开不反复响，开盖自动三声功能已获本次实物反馈。随后用户明确反馈听到响声马上贴回磁铁能提前停止，OLED 显示 `BOX HARDWARE TEST` 及 D33/Lid 状态；本轮约定的本地硬件功能测试均获实物确认，COM7 已释放。
