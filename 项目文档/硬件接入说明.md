# 药盒硬件接入协议 v0.2

软件可独立演示，硬件入口保留在“我的 → 硬件接入与设备设置”。目前没有真实硬件验证记录；首个真实心跳到达前，页面始终显示“尚未接入硬件”。

## 连接与认证

1. 运行根目录 `启动局域网联调.bat`。硬件服务器地址为电脑局域网 IP 的 8766 端口。
2. 家属登录后进入硬件设置，获取当前家庭唯一 `deviceCode`，生成设备接入密钥。
3. 将该设备编号和密钥写入固件私有配置。密钥只显示一次；重新生成后旧密钥失效。不要把真实密钥提交 Git。
4. 下面三个接口均带 `Authorization: Bearer <deviceToken>`。设备密钥与家属会话分离，不能互换。一个家庭当前绑定一个逻辑药盒。

## 心跳 POST /api/device/heartbeat

```json
{"deviceCode":"从设置页获取","battery":85}
```

`battery` 可省略，范围 0–100；未上报时显示“待上报”。建议 30 秒一次，超过 90 秒没有真实通信判定离线。可成功响应 `{"ok":true,"device":{...}}`。

## 拉取计划 GET /api/device/schedule

响应包含 `deviceCode`、带 `+08:00` 的 `serverTime`、当天三个 `tasks` 及 `reminderPolicy`。每个任务具有 `id`、`date`、`slotKey`、`startAt`、`endAt`、`medicines`、`status`、`reminderCount`。`NO_MEDICATION` 的药格不需提醒。

`reminderPolicy`：`intervalSeconds=600`，`maxCount=3`，`graceSeconds=900`。固件根据当前时间和计划实际驱动蜂鸣器/语音。服务端定时推进状态和应用内提醒；不会直接控制尚未接入的蜂鸣器。建议定期拉取、开机拉取，保持设备时钟校准。

## 开盒事件 POST /api/device/events

```json
{
  "deviceCode":"从设置页获取",
  "eventId":"设备编号-20261015-080031-0001",
  "slotKey":"morning",
  "occurredAt":"2026-10-15T08:00:31+08:00",
  "battery":84
}
```

- `slotKey` 为 `morning` / `noon` / `evening`；第一版单格传感器可配置为其中一个时段，后续三格分别映射。
- 示例时间仅用于说明格式，实际上传必须为当前真实事件时间，带时区。
- 设备负责为每次开盒生成唯一 `eventId`。网络重试使用完全相同的正文和编号；服务端返回 `duplicate:true`，不重复记历史。同一编号不同正文返回 409。
- 服务端按事件日期与时段匹配当前展示周任务，拒绝无计划药格、未来超过 2 分钟、早于 7 天以及当前周之外的事件。断网缓存跨周补传需后续扩展历史任务接口，当前不可假装补传成功。
- 事件记录来源为 `hardware`；软件模拟来源为 `demo`；时间规则产生的逾期来源为 `rule`。
- 若先前进行过模拟开盒，后来的真实开盒仍会独立保存真实来源，不能被演示记录吞掉。
- 成功开盒事件也刷新设备通信时间；设备编号与密钥不匹配返回 403。

常见错误：401 密钥无效或缺失；403 编号不匹配；409 无计划/事件冲突；422 参数或设备时间不正确。

## 数据保护与范围

已有真实设备事件的家庭禁止演示重置。仅用于软件演示的家庭可通过确认对话框恢复初始状态。数据持久化在本机 SQLite，不会自动上传云端。后续正式部署应配置 TLS、设备安全存储、账号恢复和通知服务。

开盒不等于已服药。本项目辅助家属关注日常情况，无法核实吞服，也不替代医疗判断。
